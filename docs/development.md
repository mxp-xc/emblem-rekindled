# 开发与验证

## 运行

使用 Godot 4.7.2 标准版、Compatibility 和 typed GDScript。
同一工程用于 Android 原生 App 与 Web；Web 为调试入口，无网页业务逻辑。

竖屏是默认及推荐方向；后续开发、截图和主要验收以竖屏为准，横屏作为可选能力保留兼容验证。
Android 随系统方向切换横竖屏，Web 随窗口比例适配；逻辑画布短边为720，默认桌面窗口为竖屏。
战场使用可用宽度，世界图在安全区内展开，贴图以外保留底色；不重排原地图坐标。
人物资料、档槽和独立战斗保留原版纵向信息结构，宽屏居中并按高度限制缩放。
方向或安全区变化时取消旧触点、拖动和原生按钮按压；当前页面、所选人物及未提交确认保持，需新输入才提交。
横屏验收入口见 [横屏布局与旋转验收](acceptance/landscape.md)。

```sh
rtk godot --path game --editor
rtk godot --path game
```

战场占满游戏窗口。手机滑动、电脑鼠标拖动或滚轮上下移动视野；缩放只通过游戏设置的滑块或“查看全图”调整，滚轮与双指手势不缩放。
单击角色立即显示移动范围，点击空格移动；移动后自动打开角色旁的行动菜单，双击角色也可打开。
菜单优先放在角色左右，空间不足时放上下并钳制在地图内。
点击菜单外关闭弹窗。Android 系统返回或键盘 Esc 逐层返回；从行动菜单返回会撤销尚未确认的移动，
再次返回取消选中。物品依次选择使用/装备/丢弃、物品及确认；取消按相反顺序返回，保留所选物品。
交换先在地图选择相邻同阵营人物，再在上下库存选择来源和接收位置；进入交换页后位置已确认，返回行动菜单后再返回会结束主动人物行动。
行动菜单的“状态”或键盘 `#` 打开原版全屏人物资料，左右滑动或点击左右箭头切换攻击数据、战斗力数据和武器与物品；
装备页点击物品查看详情，返回先关闭详情。敌军当前持有且匹配掉落模板的物品名称按原#00DD00标绿，图标与耐久保持原色；转移后按新拥有者重新显示。空说明武器直接显示数值，不提供空白说明页；已有说明完整分页。
资料页显示本人的专属头像或本单位形象，不借用指挥官头像；指挥官属性加成规则保留。窗口使用原版绘图器导出的像素边框。
底部状态条按原版显示人物姓名、HP与等级，或地块缩略图及回避、防御加成；移动模式保留所选人物信息。
齿轮菜单放在底部HUD右侧，避开地图格；系统菜单采用紧凑纵向列表，战场设置提供缩放、全图与音量，标题设置只提供音频等全局选项。
设置不显示字体许可入口，许可文件仍随包保留。保存成功提示在切页时清除，并在停留时自动消失。
地图镜头与点选区域扣除底部HUD，最南侧撤退格保持可见、可点。
地图两侧可留空；对白、头像、HUD、菜单及战斗界面统一限制在实际地图显示的水平范围内，随缩放、全图和窗口调整更新。
电脑宽屏下人物资料与指挥官页居中显示，按高度限制缩放，所有属性与选择器均留在屏幕内。
指挥官配置沿用原版三行选择器；编辑先保留草稿，返回时提交，仍可选择本回合已行动的英雄。
“杖”沿用选杖列表、底部原说明及地图目标选择，方向键循环目标，确认直接施放；返回按目标、杖列表、行动菜单逐层退出。
杖可对满HP同伴施放并消耗次数/获得经验，AI仍只选择受伤同伴；长物品说明在窄底栏翻页。
圣武器自疗耗尽后从背包移除，按当前库存顺序装备第一件可用武器；没有可用武器时不显示攻击，也不能反击。
这是已批准的原版异常修正：不保留已耗尽的武器效果，敌方攻击不会错误扣除药草次数；存读档保持相同状态。
菜单区域消费自己的输入，不同时操作下方地图。滚轮在当前菜单上下切换可用选项，在人物资料页按前后顺序翻页；物品详情打开时保留当前页。长物品列表跟随选中项滚动。连续同向滚动按滚动量合并，首个事件立即响应，后续最多每140ms一步；静止180ms或反向后立即响应。快速机械滚轮也遵守这一菜单限速，不积压停手后的补跳；地图平移保持连续。
行动菜单默认优先选中攻击、杖、交换、物品、待机；没有可执行操作时选中状态，列表排版保留。
游戏设置的“辅助功能”提供“直接通关”，确认后进入当前关卡既有胜利剧情、路线选择和一次结算，不额外生成击杀、经验或掉落。
仅玩家阶段的稳定战场可使用；标题、世界、剧情、演出、自动阶段和未确认的移动不可使用。确认、辅助、设置及主菜单逐层返回。
行动菜单与物品列表的鼠标悬停同步当前行；地图悬停使用像素角框并直接更新地形或人物属性，不提交操作。
攻击先选择武器，再显示完整射程和可选目标，确认目标后进入预测；交换显示相邻四格及可选同伴。
敌军依次展示移动范围、路线、移动和攻击目标，再进入战斗；范围复用同一绘制组件，敌方红色、己方蓝色。
首次经验教学替代底部人物状态条，结束后恢复。
新功能先核对原版入口和完整流程；既有组件可优化并复用，以统一、美观、易用和易维护为准。
无需为逐像素还原复制控件或增加维护成本。

启动先自动滚动原序文，确认键或点击可跳过，Back不跳过；随后进入原版标题图与横向选择器。
存在临时记录时，标题首项“读取进度”直接恢复当前战局或世界进度；“读取存档”单独打开四个命名世界档。
标题按开始游戏、读取进度、读取存档、游戏设置、游戏帮助循环；无临时记录时默认开始游戏且读取进度不可用，有记录时默认读取进度。
Back收起菜单，子页返回保留选中项。
新游戏直接播放世界地图叙事和首关入场对白，
完成指挥官选择与现代操作教学后开放行动。稳定战局从标题读取时直接恢复，不重播开场。
开场沿用原65ms目标更新周期：按原镜头余距减半、每轴1–12原像素移动，镜头到位后再执行入场或对白。
单位按每更新12原像素移动；北方六人并行入场落点后保留原队列停顿，两侧飞鸟按当前展示要求随北军提前显露，避免镜头离开后才出现。
南方显现等待10次更新，再回镜头开对白。开场没有HUD时地图使用完整有效高度。
数据中的原等待及对白后等待均实际执行，普通确认不能越过动画门闩。宽屏对白与实际地图同宽，字号仍按高度限制缩放。
战术地图“保存进度”只接受玩家阶段的行动间隙；移动尚未确认、剧情和演出期间不能保存。
临时继续记录为`user://battle_save.json`，首关结算及世界图返回标题也保留到该记录。
四个命名世界档为`user://battle_save_slot_1.json`至`battle_save_slot_4.json`，仅由明确的世界记录操作写入，
与临时档彼此隔离。选择器左右切槽，详情显示战次、地点和累计时长；空槽显示“(空)”，确认读取空槽仍留原窗。
覆盖已有记录先显示原样式确认条，取消保留槽位；读取已存世界档直接恢复世界图，返回按确认、档槽、来源菜单逐层退出。
预览先校验正文；坏档与写入失败留在当前槽显示错误，不改其他记录。
新游戏累计前台游玩时间，菜单与剧情计入，后台及标题等待不计；读档续计。未记录时间的旧档显示“—:—”。

战斗结算后保留可操作世界图，按已选路线揭示下一节点；选择地点更新地名栏，当前地点的确认键打开世界菜单。
已访问地点可直接往返，不重打旧战；当前驻留地点随世界记录保存，商店按驻留地点取商品。
福尔斯路线可确认前往索菲亚山脉（第2战），取消前往不写记录。世界移动与入场叙事后，播放该战开场、目标和指挥官设置。
正式队伍培养、物品、仓库和资金跨关保留；福尔斯按第二战原部署加入。战斗记录使用实际关卡身份，旧首关记录仍可读。
“换取金币”为默认开放的本地测试福利，每次直接领取1000金币，可重复，上限9999999。
领取成功先保留到当前继续记录，不自动覆盖四个命名档；写入失败不增加金币。
世界菜单的“物品整理”先横向选择正式角色，再进入商店、仓库或交换。
驻留世界人物使用原两帧待机，目标周期390ms，世界菜单打开时暂停。整理页与资料页的单位图标裁掉透明留白后等比放大。
仓库按人物6件、仓库40件限制存取，不能装备的物品仍可持有；双方满背包时可交换已有项。
最后一件存取后自动切到非空页签，普通返回依次经过确认、物品列表、页签、人物操作和总览，再回世界。
世界交换不要求相邻、不消耗行动，复用双库存界面；退出物品页按当前顺序选择第一件可装备物品。
普通商店本地默认开放，商品和价格来自当前队伍所在节点的原表；可重复购买，次数是默认耐久而非库存量。
背包满时买入物品转入仓库，资金不足或两个容器都满时保留原值；卖价按原半价及剩余次数折算。
密之匙在进入商店时消耗，只决定本次特殊商品，不做支付或永久激活。
确认改动物品后先写当前“继续”记录，再更新界面状态，失败保持原物品和资金；四个命名档仍只由明确记录操作写入。
物品说明复用现有底栏，长仓库列表使用可触控滚动及键盘焦点跟随。
当前已登记关卡以[章入口](../game/content/chapter_1/chapter.json)的 `battles` 为准，
最新接入南部平原m3配置；本关运行时与平台验收状态见[#37](https://github.com/mxp-xc/emblem-rekindled/issues/37)。
未接入节点显示制作中并保留进度，后续关卡与标题外围入口逐阶段推进。

## lint、格式化与测试

开发依赖由 `bun.lock`、`uv.lock` 固定，不参与正式游戏运行。

```sh
rtk bun install --frozen-lockfile
rtk uv sync --locked
rtk bun run format
rtk bun run lint
rtk bun run check
```

- `format`：gdformat 格式化 GDScript，Ruff 整理 Python imports 并格式化，Prettier 格式化 Java 和 JSON。
- `lint`：gdlint、gdformat 检查、Ruff 规则及格式检查、Prettier 检查；只检查，不改文件。
- `check:quick`：lint 和工具测试；提交前自动运行。
- `check:parse`：导入并在单个引擎中解析全部脚本。
- `check`：完整检查，行为测试逐个隔离运行；推送前自动运行。
- `setup:hooks`：仅为当前 checkout 安装检查 hooks，保留已有自定义配置。
- `.editorconfig` 约定缩进、换行与尾随空白。gdlint 保留校验函数的提前返回，其他规则正常启用。

日常单文件验证和脚本检查：

```sh
rtk uv run python tools/check_godot.py --test test_map_input.gd
rtk uv run python tools/check_godot.py --parse-only
```

检查器会识别 Godot 的错误输出，即使引擎返回 0 也判失败；每次引擎调用有 60 秒超时，中断时会清理其拥有的引擎进程组。
`--test` 可重复指定；完整检查显示阶段和测试进度。故障清理测试分别计算启动等待与运行超时。
平台交付与界面证据要求见 [验证与复核](agents/verification.md)。
Godot 4.7.2 / Android 16 / targetSDK36 实测一次系统 Back 会重复发出返回通知，入口合并100ms内的重复系统请求；键盘 Esc 独立处理。
故意产生运行时错误的检查器测试使用系统临时目录，不进入正式资源。

## 快速回归与内部状态读取

最新debug APK已导出且模拟器已启动时，可运行完整首关的实际ADB回归：

```sh
rtk uv run python tools/playtest_first_battle.py --speed 32
```

驱动先安装当前`build/android/emblem-rekindled.apk`（也可用`--apk`指定），再从新游戏开始。
AVD Quick Boot可能恢复快照中的旧安装，不能以已有图标判断包已更新。
移动、装备、攻击、治疗和确认均走真实输入；通过内部只读接口规划下一步，
只在每回合开始保存一次。默认32倍时钟，正常节奏与动画完整性另用1倍验证。
结果、回合记录及逐步JSONL证据写入`temp/playtest/`，失败额外保留截图、状态和进程日志。
普通随机结果保留；测试控制器保护必存活治疗者，不复用可牺牲NPC的前进策略，仍可能因战局失败而退出。
开始前完整备份并独立核对已有记录；失败则停止。结束后先恢复全部原JSON，再清理新增记录并逐字节验证。
备份和恢复凭证在批次的 `records/` 中；恢复失败保留备份，可用 `tools/qa_records.py` 重试，详见验证文档。
默认结束后关闭模拟器。
同一验证批次需保留模拟器时显式使用`--keep-emulator`；多设备用`--serial`指定。

完成标题序文后，可通过只读接口查看状态，并从游戏界面选择测试速率：

```sh
rtk uv run python tools/android_playtest.py read
rtk uv run python tools/android_playtest.py speed 32
```

游戏设置中的“游戏速率”提供1、2、4、8、16和32倍，仅当前应用会话生效；切换关卡与返回标题保留，每次重新启动或刷新回到1倍。
速率不写入长期设置或任何存档，累计游玩时间仍按真实前台时间计算。自动化通过相同界面选择32倍，选择后设置页保持打开，按所在页面逐层返回。
debug原生、本地和Web均提供只读诊断服务；收到显式请求才写出响应，release不启用。诊断服务不读取速率配置文件，也不改变游戏速率。
Android接口通过ADB可访问的应用私有文件交换请求与响应，不依赖网络权限或HTTP服务。
请求与响应均原子发布，并用`requestId`关联；单个客户端串行读取。
读取返回真实战局快照、世界进度、界面就绪状态和可见控件坐标；不执行业务命令，不保存进度、不推进RNG。
`ready`表示玩家行动间隙；演出中的快照可以读取，但不能作为可恢复的稳定存档。
Android请求发布与匹配响应等待在一次ADB调用中完成；未就绪时按状态继续等待。

## 原版资源整理

正式运行只读取 `game/` 内已准备的数据、PNG、Ogg 和字体，不读取原 JAR、模拟器或提取工具。
章入口显式引用生成结果；生成器只发布已声明拥有的生成文件，并登记关卡入口，不覆盖 `authored/`。

```sh
rtk uv run python tools/import_chapter_1.py --plan
rtk uv run python tools/import_chapter_1.py --emulator /path/to/freej2me_plus.jar --battle m3 --report temp/m3-import.json
rtk godot --headless --path game --import
```

输入为本地 `reference/original-jars/chapter-1.jar`，SHA-256：
`67d1c77e823816e203244a15428ba9fb635d40edba04efa3180b3334025989fe`。
离线绘制复用 [FreeJ2ME-Plus](https://github.com/TASEmulators/freej2me-plus) 的现有本地构建，
其 JAR 必须匹配 SHA-256：
`9c59b74ae8e4fad205e5ff186940c24c53480918a3b180bb551559db9be3e7ff`。
同名 nightlies 可能改变；不匹配时拒绝导入，不自动下载或静默换包。
受控原包调用沿用 `-Dfile.encoding=ISO_8859_1`；已观察到改写该属性别名后，现有参考运行器在加载阶段直接退出，不能只凭进程返回0判断采样成功。
历史 RMS 快照不参与导入；机器上的参考运行器路径记在可选 `AGENTS.local.md`。

工具默认使用 PATH 中的 `java` / `javac`；其他位置通过 `--jdk /path/to/jdk/bin` 指定。
地图更新保留已有Ogg，不重复合成音乐，无需为扩一关重新运行ffmpeg。
工具在隔离临时目录中调用原始初始化器与绘图器，固定准备阶段随机源。用 `--battle` 指定目标关卡；
默认选择覆盖所缺人物表现的最少路线上下文，再补齐全章动作缺项。`--route` 可指定优先准备的原路线，
其余上下文仍由工具按缺项补充，不能用该路线替代其他路线的真实表现。
原生准备按路线前缀结算并加载目标地图，剧情、目标与事件由已核对的 `authored/battles/mN.json` 承载。
首关两条有效位置调整和初始敌军状态在离线规范化时应用，不在运行时按地图编号分派。
这不是自然游玩记录；普通敌军初始 HP 可与旧运行样本不同。两战各有32条记录，首关29个、第二战23个初始可见单位。
地图人物使用原版两帧待机/移动循环，原阈值为300逻辑单位，即6次50单位地图更新；按65ms目标周期换算为0.39秒。
行动结束切换原版灰色静态帧。
治疗在目标格显示原青白圆环，HP逐步增加；战后按原队列显示破损、掉落、经验和成长，
首次玩家阶段经验后显示逐行滚动教学。自动计时的消息无需额外确认，演出不重新执行结算。
独立战斗素材与演出已接入；首关整体按模拟器与Web验收，真机暂不作为本轮完成条件。

`provenance.json` 记录来源与拥有的输出路径；来源JAR仍按上面的固定身份核对。
图片共享直接比较完整PNG字节及Godot导入参数，不新增内容摘要。共享所有权、重导入清理和改图入口见下一节。
地图、战斗、标题、世界地图及胜败音乐从原 `p.mid`、`battle.mid`、`title.mid`、`world.mid`、`win.mid`、`over.mid` 离线合成为 Ogg。
胜败音乐播放一次，其余循环；采用 JDK 默认合成音色，不附带运行时 MIDI 插件，音色不等同于原手机合成。
长背景音乐显式使用Stream播放，避免Web Sample在循环/重复恢复时复制完整音频缓冲区。
音乐解锁只恢复已暂停的播放；标题切项、菜单返回和地图鼠标移动保持当前播放位置，后台恢复也不重播。
字体来自 Noto CJK，来源与摘要在 `ui/fonts/source.json`，完整 OFL 随包保留。

### 章内共享图片与改图

`generated/shared/` 由章级 `provenance.json` 统一拥有。各关保留地图和原始部署；
`generated/library/` 拥有人物表现、UI、文本、动作和片段，关卡通过recipe与stage/scene引用。
JSON中的图片路径可以引用shared目录。相同PNG字节与相同导入参数
只保存一份；同名异图、同图不同参数仍分别保存。普通Godot导入和导出直接使用这些PNG，
无需原JAR、展开素材包、运行时目录扫描或额外挂载资源包。

`tools/chapter_assets.py::share_textures()` 是离线共享入口，资源导入器在发布某关后调用。
各关 `provenance.outputs` 只拥有本关私有输出；共享图片只属于shared的清单。
清理先核对全部所有权与章内JSON引用，再删除没有引用的共享图片及其 `.import`。
重导入同一图片复用现有公共路径；同源文件内容变化时分配另一个路径，其他关仍可使用旧图。
每关的 `textureSources` 记录原始图片路径到共享图片的离线映射，重导入时沿用该来源已选择的
导入参数；新图由Godot分配新UID，仍在使用的旧图保留原UID。映射不参与游戏运行。
`authored/` 的声明保持原样，其引用的私有图片保留稳定路径；章入口由导入器登记关卡，但不改写人工资源声明。
`.import` 保留Godot导入参数和UID，移动后由Godot重建导入目标路径；`.godot/`仍为可重建缓存。
运行时要修改共享Texture通过 `get_image()` 取得的Image（如缩放主题图片）时，
先调用 `duplicate()` 取得自己的Image，再执行 `resize()`、`crop()` 等修改；纯读取无需复制，
不能修改ResourceLoader共用的原图。

修改图片时按作用范围选择：

- 所有使用方一起改：通过关卡manifest找到共享PNG，直接编辑该PNG；预览后检查所有引用方。
  它仍属于生成快照，下次重新提取来源可能为当前关恢复原版图片，人工长期改图使用下一种方式。
- 长期人工换图：将同尺寸PNG放入 `authored/`，在章入口 `textureOverrides` 指向的
  `authored/texture_overrides.json` 中登记源PNG到替换PNG的绝对 `res://` 路径。
  例如 `{"res://content/chapter_1/generated/shared/battles/m1/map_units/unit_0/active_0.png":
"res://content/chapter_1/authored/custom/hero.png"}`。替换作用于全章使用该源图的引用，
  不改原PNG、帧定义或生成catalog；空表等价于原表现。目标必须位于该表所在目录或子目录，
  且为可加载的同尺寸PNG；未知源图、越界路径和尺寸不符在打开关卡前报错。
  生成器保留表和私有图片，后续扩关只更新生成库，不需要复制或同步整份catalog。
- 新增一关：导出该关自己的定义与新增视觉差异，再经过共享入口；先比较图片和导入参数，
  不能按部署ID、角色名或文件名推断相同。扩关验收包含“重导入旧关，新关资源仍可加载”。

此前按关保存完整视觉输出，会把同一图片在不同装备、动作和关卡中重复保存；
只让第二关引用第一关私有文件，又会让第一关清理误删第二关素材。现在由章拥有公共图片，
关卡只拥有私有输出，避免这两类问题。新增生成器应沿用这一所有权关系，
不要另建逐关公共素材副本。图集仅在新的文件治理或性能证据支持时另行评估，见
[Godot素材组织调研](research/godot-texture-packing.md)。

### 配置扩关与片段缺项

最终数据和打开接口见[配置驱动扩关设计](design/chapter-content.md)。本轮接入状态仍以[#36](https://github.com/mxp-xc/emblem-rekindled/issues/36)
及各关实施票为准；能解析某张地图不等于该关已通过实际流程验收。

先核对原版事件，编写 `authored/battles/mN.json`，再按原路线导入地图/部署和章库缺项。
新关文本通过 `{ "sourceTextIndex": 499, "speakerId": 82 }` 引用章级654条原文本；
需要人工改写时提供完整 `text`。同一关不为每条路线保存完整人物或片段副本。

`--plan` 不调用原JAR，列出所有已登记关卡在当前共享profile和stage下需要的组合与缺项。
`--chapter temp/<batch>/game/content/chapter_1` 可在显式章副本演练同一正式导入入口。
`--native-input <directory>` 可重复指定已准备的原生输出；工具核对来源、路线、部署绑定及片段依赖，
不能把依赖尚未合入章库的增量输出当成完整输入。缺依赖时重新准备该上下文。
`--report` 记录所选上下文、采样与复用数量、闭包和发布结果。
未变化的JSON保留现有字节；新数据或语义变化的数据使用项目Prettier格式化后发布，
相同输入重入不应产生格式diff。人工配置和已有PNG的导入参数、UID保留。
普通导入向原生采样器提供已有stage的完整契约与真实文件清单，契约完全相同时仅采样缺少的组合；
`--refresh-motion` 显式重采当前原生上下文，用于核对采样规则变化，不覆盖冲突的旧片段。
需要保留独立原生输出时添加 `--native-output temp/<batch>/<name>`；该模式不发布游戏内容。

发布先在隔离的完整章副本合并库和地图，再检查所有已登记地图的动作组合闭包。
新关给共享profile增加武器时，旧关可能新增“该动作×旧敌人形状”的组合；
不能只检查新关自己的原生输出。已有m0/m1实际样本曾缺36个组合，补齐后统一校验；
相应行为测试保护“旧关缺片段时整章不发布”。复制图片、缩减合法装备或放宽运行时校验都不能补齐这些动作。

库中的PNG/clip引用落盘使用绝对 `res://`；投影交给现有控件时统一使用派生的
`content.entry.resourceDirectory = "res://"` 作为资源基准。临时 `user://` 配置的位置不改变随包资源基准。

## 导出

下载[官方 4.7.2 模板](https://github.com/godotengine/godot-builds/releases/tag/4.7.2-stable)中的
`Godot_v4.7.2-stable_export_templates.tpz`，然后验证并只提取所需平台：

```sh
rtk uv run tools/prepare_templates.py /path/to/Godot_v4.7.2-stable_export_templates.tpz
rtk bun run build:web
rtk bun run build:android
rtk bun run serve
```

模板放在忽略的 `build/templates/4.7.2.stable/`，不修改全局模板安装。
预设引用同版 Android、单线程 Web 与 ICU 数据。中文明确包含 ICU；测试、来源记录和工具不进正式包。

Android 需在 Godot 编辑器设置的 Export → Android 中指定已安装的 Java SDK 与 Android SDK。
机器上的路径、工具版本和 AVD 信息记在可选 `AGENTS.local.md`。
Android验证批次结束且短期无需继续测试时关闭模拟器，避免持续占用宿主资源。
导出命令临时注入 buildId，验证包内身份后发布到 build/；失败不发布未验证的包。
源目录中的临时身份文件在导出结束后恢复，生成身份不进入版本控制。

APK 写入 `build/android/`，Web 写入 `build/web/`；产物可在脱离仓库的位置启动。
本地预览固定使用 `http://127.0.0.1:8765/`，重新导出后普通刷新即可，不加版本查询参数。
Web入口的base指向`build/web/<buildId>/`，JS、WASM、PCK和音频worklet随构建使用独立资源URL；旧版本目录保留给仍在运行的页面。
`serve` 对资源设置 `Cache-Control: no-store`；不发送清理浏览器数据的响应头，IndexedDB、cookies和其他缓存保持原状。
默认只监听本机，其他本地端口用 `bun run serve --port 8766`。
普通 `http.server` 可能让浏览器复用旧 PCK，不用于游戏开发预览。
Web 由本地静态 HTTP 提供，首个用户操作后才启动音频；设置通过 `user://` 持久化。
本轮以现有 Android 模拟器验证触屏、系统返回、后台恢复、存储及音频输出信号，配合电脑 Web 同流程。
真机测试暂缓；模拟器通过不代表实体手机安全区、性能或扬声器听感已验证。
