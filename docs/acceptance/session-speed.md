# 会话游戏速率与测试耗时

实施入口：[#29](https://github.com/mxp-xc/emblem-rekindled/issues/29)。
游戏内速率已实现并通过自动检查及 Android/Web 自测；Android 自动化改用软件渲染及无窗口模式后，同一 APK 的固定流程缩短超过一半。Web 已定位清理缓存响应头引起的导航停顿，并改用独立构建资源 URL。开发自测与用户集中验收分别记录。

## 当前行为

自动化通过游戏设置选择速率，操作入口见 `docs/development.md`，不再修改速率配置文件。
竖屏继续作为默认和主要验收方向。

## 耗时结果与范围

证据与复现脚本在 `temp/qa-speed/README.md`。对比固定为已经使用32倍的旧流程与通过新 UI 选择32倍的流程，包含启动、移动/战斗、保存、冷重启和记录恢复；不包含导出、安装。

| 项目 | 旧流程（host） | 当前包（host，三次中位数） | 当前包（软件渲染/无窗口，两次） |
| --- | ---: | ---: | ---: |
| 总耗时 | 15.467秒 | 28.710秒 | 11.889～12.618秒 |
| 移动与战斗 | 1.711秒 | 1.275秒 | 1.123～1.262秒 |
| 保存 | 0.533秒 | 0.359秒 | 0.347～0.348秒 |
| ADB 调用 | 226次 | 119次 | 111～112次 |

host 样本第一次状态可读需约16秒，冷重启对应等待约4秒；旧进程日志表明约12秒发生在引擎版本输出到 OpenGL 初始化完成之间，期间提示缓存 shader 加载失败。软件渲染/无窗口样本对应图形初始化约1秒，第一次查询约2.5秒；相对当前包 host 固定流程减少56%～59%，相对更早旧实现 host 基线减少18%～23%。两个模拟器启动选项同时改变，尚未单独归因于某一个选项；不能将这些结果称为产品本身的性能提升，也未证明 Web 或所有整关回归减半。本机自动化启动参数已记录在 `AGENTS.local.md`。

Web 使用相同 HTML、同源资源和相同导航接口进行对照：增加旧 `Clear-Site-Data: "cache"` 头后，导航在10秒内未返回，约60秒观察仍停留在原页面；服务器收到 HTML 请求后，未出现该页面后续资源请求。无清理头别名页的同一导航调用211毫秒返回，页面 load 为136.5毫秒。慢样本没有完整 load 时间，不将观察期限当作完整耗时。

移除该响应头、使用 buildId 独立资源 URL 后，原地址三次 load 为250、93.1、96.6毫秒，JS/WASM/PCK 开始请求的时间为导航后约28～60毫秒；一次从原地址导航到捕获实际构建的运行画面用时1.148秒，包含工具调用开销。这些是本机当前浏览器样本，不等同于所有设备的启动耗时。临时对照 HTML 已清理，普通预览服务已恢复；原记录完整备份保留。

最终 Web 导出10.819秒、Android导出20.138秒，后者安装命令报告0.808秒；独立记录在 `temp/qa-speed/export-timing.json` 及批次证据中，不并入上面的运行流程同比。
