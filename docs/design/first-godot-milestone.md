# Godot最小工程实施计划

对应[建立首关竖屏Godot工程并验证Android/Web最小运行](https://github.com/mxp-xc/emblem-rekindled/issues/10)，遵循[工程与文件系统组织设计](project-organization.md)。本计划规定阶段范围与验收，实际进度和证据以实施issue为准。

## 阶段结果

同一Godot工程能够在Android手机和电脑浏览器中显示真实首关地图及开局单位，支持拖动、点选查看、定位和缩放，播放一段随包音频，并验证设置保存与重启恢复。它是完整首关开发的基础，不是完整可玩的首关。

本阶段不实现移动/攻击结算、敌方AI、完整剧情、独立战斗演出或完整战局存档；这些仍属于后续首关范围，独立战斗演出不从完整首关验收中删去。后两章和横屏不在本阶段展开。

## 实施顺序与完成条件

### 1. 建立最小启动与竖屏显示

- 建立实际需要的game/project.godot、app/启动场景和导出预设，使用4.7.2标准版、typed GDScript、Compatibility。
- 以720×1280设计尺寸组织竖屏布局，实际输出按设备分辨率绘制。地图像素缩放与UI文字/控件分开；游戏窗口铺满一体战场，按钮贴边，状态按点选显示，低频设置收菜单。电脑Web使用同一场景和输入规则，手机滑动、电脑鼠标拖动移动视野。
- 确定随包中文字体及来源；需要下载或新增工具时先对齐，不依赖本机恰好安装的字体。
- 通过条件：启动入口明确，中文可显示，页面能在目标长宽比下完整布局；此时尚不宣称Android/Web导出通过。

### 2. 整理真实首关数据与随包资源

- 在content/chapter_1/建立章入口和本阶段实际需要的地图、开局单位、图片等。生成器拥有generated/，人工编排和后续替换素材进入authored/，章入口明确选择生效定义。
- 将原始资料转换为项目自身可用的格式，保留逻辑格坐标、帧裁剪和锚点等显示所需信息；规则不得根据PNG像素尺寸推导地图位置或身份。
- 通过条件：地图尺寸/格数据、开局可见单位和位置与参考样本一致，资源引用能加载；脱离原JAR及整理工具后，正式运行资源仍然完整。

### 3. 实现地图查看与输入

- 在features/tactical_map/就近组织场景和专用脚本；单位与地格身份来自章内容，不写入贴图文件名或节点显示文字。
- 提供拖动、单位/地格点选、状态查看、定位和缩放。键鼠与触屏共享游戏操作；界面控件消费的输入不能同时触发地图。
- 通过条件：非原点位置能够正确选中；拖动结束不会误选；镜头移动/缩放后仍能准确转换坐标；单位状态面板与所选对象一致。
- 实测区分鼠标事件与触摸事件。MCP发送了输入或桌面鼠标可用，都不能代替Android触屏通过。

### 4. 接入一段音频与设置持久化

- 原曲离线转换后随包播放，优先采用既定Ogg方向。先处理代表曲目，不批量引入全部曲目；转换工具和音色来源需要新增时先对齐。
- 检查播放、循环、暂停/恢复；Android后台恢复与Web首次用户操作后的音频解锁分别验证。
- 通过音量等真实设置的保存、重启恢复验证persistence/入口，使用独立设置记录。不要把测试计数或临时探针当作游戏进度，也不要因为设置恢复成功就标记战局存档完成。
- 通过条件：重新启动后设置确实恢复，读取/写入失败明确报告；没有改变既定正式战局存档的行动间隙、随机结果或安全写入契约。

### 5. 建立导入与行为检查入口

- 沿用官方CLI，在首次导入后检查脚本和资源。需要辅助命令时保持直接，不自建构建框架。
- game/tests/覆盖本阶段已实现的内容引用、输入坐标转换和设置读写等有价值行为；通过相同业务入口验证。没有实现战斗规则时，不为不存在的规则建立占位测试。
- 至少用缺失资源/非法引用等已知坏例证明检查能够失败。工具初始化success或脚本解析成功，不代表场景运行和业务检查成功。
- 通过条件：入口、退出状态和错误位置可用于排错；正式导出不包含测试脚本，JSON等动态加载文件有明确包含规则。

### 6. 准备匹配模板，完成Android/Web导出

- 到导出步骤前再对齐4.7.2 Android/Web模板及中文所需ICU数据；模板未准备前不把导出项勾选为完成。
- 同一工程维护Android和Web预设，产物分别写build/android/、build/web/，实施时配置忽略构建输出。
- 首期采用标准导出，不预先加入自定义原生工程、NDK/CMake或Web构建工具链。确有需要时再按实际依赖核对。
- 通过条件：仅使用导出目录即可启动，不访问reference/、tools/、历史缓存或外部解析服务；开发插件、运行探针和测试资源没有成为正式包依赖。

### 7. 分别记录平台验收

| 平台/检查 | 必须记录的结果 |
| --- | --- |
| Android真机 | 设备/系统、竖屏、安全区与中文、触摸定位/拖动、音频、设置重启恢复、后台恢复。没有真机结果就保持待验收。 |
| 电脑Web | 浏览器与本地HTTP入口、键鼠/缩放定位、音频解锁、设置刷新/重开恢复、标签页切换。 |
| 布局样例 | 1080×2400、1440×3200及16:9的竖屏布局/像素缩放结果。模拟尺寸是显示检查，不替代实际手机。 |
| 独立运行 | 核对包内资源并从导出产物启动；没有原包、开发服务或工具时仍可运行。 |

## 工具安排

官方CLI是必要入口；第三方skill/MCP不是此阶段的前置条件。若最小可运行场景中出现明确的观察/输入痛点，再按[AI工具适配调研](../research/godot-ai-tools.md)对一个候选做隔离试用。安装来源/版本、依赖、运行探针及客户端配置先对齐，不为某个候选预造兼容层。

JDK/SDK路径使用已核对的本机配置，不修改全局Java。音频转换工具、字体及导出模板是否需要新增，分别核实；当前环境批准不自动覆盖这些安装。
